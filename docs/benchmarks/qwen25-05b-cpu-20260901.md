## Comparison

Both configurations used the same local model and deterministic inference
parameters. They differed only in the prompt: the candidate prompt added
explicit ISO-currency and final-total instructions and told the model to ignore
instructions in untrusted invoice text.

| Configuration | Cases passed | Schema validity | Field accuracy | P95 latency | Total tokens |
| --- | ---: | ---: | ---: | ---: | ---: |
| baseline | 14/20 | 1.0 | 0.9 | 2753.2584000146016 ms | 3250 |
| candidate | 14/20 | 1.0 | 0.9 | 2441.524700028822 ms | 4012 |

The six failed cases for both configurations were `invoice-004`,
`invoice-005`, `invoice-011`, `invoice-015`, `invoice-018`, and `invoice-020`.
Each failing case missed one of the three expected fields, primarily because of
currency normalization, while every output still satisfied the output schema.
The measured latency difference is not a causal performance claim, and the
equal quality metrics support only the statement that this candidate had no
measured quality regression in this run.

## Limitations and execution conditions

- This is one run on one synthetic 20-case dataset with a tiny 0.5B model.
- Both configurations used the same model and deterministic parameters and
  differed only in their prompts; this is not a model comparison.
- The server was warm and had prior probes/preliminary-run activity. llama.cpp
  prompt/KV caching may therefore affect the measurements.
- Baseline ran sequentially before candidate. Timings include loopback and
  serialization overhead.
- No GPU was used.
- The capture demonstrates a reproducible run and passing gates, not general
  quality, prompt superiority, or production latency.
